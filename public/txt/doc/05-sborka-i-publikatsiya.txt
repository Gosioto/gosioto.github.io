================================================================================
  05. Сборка, скрипты и публикация
================================================================================

Команды npm (package.json)
--------------------------
  npm run dev      — локальная разработка (next dev)
  npm run build    — production-сборка (next build → каталог out/)
  npm run start    — next start (для статического export обычно не используется
                     на GitHub Pages; имеет смысл при SSR-сервере)
  npm run lint     — проверка ESLint
  npm run export   — в текущем package.json дублирует next build

Статический экспорт
-------------------
  next.config.ts задаёт output: 'export'. После успешного build артефакты
  находятся в out/. Их нужно раздавать как обычный статический сайт.

Типичный сценарий GitHub Pages (project site)
---------------------------------------------
  1. Ветка (часто gh-pages) или GitHub Actions загружает содержимое out/
     в корень ветки, из которой включён Pages, либо в /docs — в зависимости
     от настроек репозитория.
  2. В настройках Pages указывают источник (ветка/папка) и при необходимости
     кастомный домен.
  3. Если сайт обслуживается с пути /Gosloto-site/, для корректных путей к
     ассетам может потребоваться basePath в next.config — проверьте фактический
     URL после деплоя; при кастомном домене на корне сайта basePath часто не нужен.

Переменные окружения
--------------------
  Для чистого статического лендинга часто достаточно без .env. Если позже
  добавятся вызовы API, учитывайте: секреты не попадают в клиентский бандл
  без явной необходимости; для static export серверных секретов в рантайме нет.
